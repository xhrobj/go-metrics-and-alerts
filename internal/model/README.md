# Модель метрики

Пакет `internal/model` содержит общую модель метрики, которую используют Агент, сервисы, хранилища и транспортные адаптеры.

```text
HTTP JSON ───────┐
                 ├──> model.Metrics ──> service ──> repository
gRPC protobuf ───┘
```

Типы, относящиеся к конкретному транспорту, преобразуются в `model.Metrics` на границе транспортного слоя.

## Типы метрик

Проект поддерживает два типа метрик:

- `gauge` - произвольное значение `float64`; новое значение заменяет предыдущее
- `counter` - изменение типа `int64`; новое значение прибавляется к накопленному счётчику

Для типов используются константы `model.Gauge` и `model.Counter`.

## `Metrics`

```go
type Metrics struct {
  ID    string   `json:"id"`
  MType string   `json:"type"`
  Delta *int64   `json:"delta,omitempty"`
  Value *float64 `json:"value,omitempty"`
  Hash  string   `json:"hash,omitempty"`
}
```

Поля структуры:

- `ID` - имя метрики
- `MType` - тип `gauge` или `counter`
- `Delta` - изменение counter
- `Value` - значение gauge
- `Hash` - историческое поле JSON-модели, не используемое текущей реализацией

Подпись HTTP-сообщения вычисляется для всего тела и передаётся через заголовок `HashSHA256`, поэтому поле `Hash` при текущем обмене не заполняется.

## Указатели `Delta` и `Value`

Поля `Delta` и `Value` объявлены указателями, чтобы различать два состояния:

- поле отсутствует
- поле присутствует и содержит нулевое значение

Например, для gauge значение `0` является корректной метрикой и не должно восприниматься как отсутствие `Value`.

При обработке входных данных:

- для gauge требуется непустой `Value`
- для counter требуется непустой `Delta`

Такая модель используется как при JSON-обмене, так и после преобразования protobuf-сообщений.
