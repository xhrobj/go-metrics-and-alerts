# internal/config

Пакет содержит структуры конфигурации и функции загрузки настроек Агента и Сервера из значений по умолчанию, JSON-файлов, флагов командной строки и переменных окружения.

## Структура

- `agent.go` - конфигурация Агента, флаги, env и `GetAgentConfig`
- `agent_file.go` - загрузка параметров Агента из JSON
- `server.go` - конфигурация Сервера, флаги, env и `GetServerConfig`
- `server_file.go` - загрузка параметров Сервера из JSON
- `env.go` - чтение и преобразование переменных окружения
- `validation.go` - проверка итоговой конфигурации

## JSON-файл конфигурации

Путь задаётся:

- флагом `-c` или `--config`
- переменной окружения `CONFIG`

Примеры:

- [`configs/agent.example.json`](../../configs/agent.example.json)
- [`configs/server.example.json`](../../configs/server.example.json)

## Приоритет источников

```text
env > flag > JSON > default
```

Для пути к JSON-файлу:

```text
CONFIG > -c/--config
```

## Валидация

После объединения всех источников проверяется уже итоговая конфигурация.

Для Агента:

- адрес Сервера не пустой
- интервалы опроса и отправки положительные
- `RATE_LIMIT` положительный

Для Сервера:

- адрес запуска не пустой
- интервал сохранения неотрицательный
- `TRUSTED_SUBNET` пустой или содержит корректный CIDR
- `AUDIT_URL` пустой или содержит корректный HTTP/HTTPS URL с host

Ошибки преобразования env содержат имя переменной и исходное значение.

## Путь к файловому хранилищу

Сервер поддерживает две env-переменные:

- `FILE_STORAGE_PATH` - историческое имя
- `STORE_FILE` - имя из JSON-конфигурации и позднего инкремента

Если заданы обе, `STORE_FILE` имеет более высокий приоритет. В JSON используется поле `store_file`.
