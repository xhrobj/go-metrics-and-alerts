# internal/repository

Пакет содержит реализации хранения метрик и общие ошибки repository-слоя. Он используется и Агентом, и Сервером.

Бизнес-логика Сервера находится в [`internal/server/service`](../server/service/README.md). Repository отвечает за чтение, запись и snapshot данных и не зависит от transport-слоя.

## `MemStorage`

Потокобезопасное in-memory хранилище на картах gauge и counter.

Используется:

- Агентом как локальное хранилище текущих gauge-метрик
- Сервером как основное runtime-хранилище, если PostgreSQL не настроен

Поддерживает одиночные и batch-обновления, чтение значений и создание независимого snapshot.

## `PostgresStorage`

Персистентное хранилище Сервера на PostgreSQL.

Поддерживает:

- upsert gauge
- атомарное накопление counter
- batch-обновление в транзакции
- чтение отдельных метрик
- snapshot всех метрик

Используется Сервером, если задан `DATABASE_DSN`.

## `FileStore`

`FileStore` не является runtime-repository для handler'ов. Он сохраняет snapshot `MemStorage` в JSON-файл и восстанавливает данные при старте.

Интерфейсы:

- `Snapshotter` - источник снимка для `Save`
- `Restorer` - получатель значений для `Load`

Файловый режим применяется только вместе с `MemStorage`.

## Ошибки

`ErrMetricNotFound` используется, когда запрошенная метрика отсутствует. Сервис Сервера сохраняет эту ошибку доступной через `errors.Is`, а transport-слой преобразует её в соответствующий результат API.
