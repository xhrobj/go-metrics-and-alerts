# Хранилища метрик

Пакет `internal/repository` содержит реализации хранения метрик, файловое сохранение состояния и общие ошибки слоя хранения. Пакет используется Агентом и Сервером и не зависит от HTTP- или gRPC-транспортов.

## `MemStorage`

`MemStorage` хранит gauge- и counter-метрики в отдельных `map` и защищает доступ через `sync.RWMutex`.

Хранилище используется:

- Агентом для локального хранения текущих gauge-метрик
- Сервером, если подключение к PostgreSQL не настроено

`MemStorage` поддерживает:

- замену значения gauge
- накопление delta counter
- пакетное обновление под одной блокировкой
- чтение отдельных метрик
- создание независимого снимка всех метрик

Метод `Snapshot` возвращает копии внутренних `map`, поэтому вызывающий код не получает прямого доступа к состоянию хранилища.

## `PostgresStorage`

`PostgresStorage` хранит метрики Сервера в PostgreSQL.

Хранилище поддерживает:

- замену gauge через upsert
- атомарное накопление counter через upsert
- пакетное обновление в одной транзакции
- чтение отдельных метрик
- получение снимка всех метрик

Gauge и counter с одинаковым именем считаются разными метриками, поскольку первичный ключ таблицы состоит из имени и типа.

При ошибках PostgreSQL класса connection exception операция повторяется с задержками `1s`, `3s` и `5s`. Отмена переданного контекста прекращает повторные попытки.

`PostgresStorage` используется Сервером, если задан `DATABASE_DSN`.

## `FileStore`

`FileStore` не является рабочим хранилищем для сервиса и транспортов. Он сохраняет снимок `MemStorage` в JSON-файл и восстанавливает данные при запуске Сервера.

```text
MemStorage
    │ Snapshot
    ▼
 FileStore
    │ JSON-файл
    ▼
 FileStore
    │ SetGauge / SetCounter
    ▼
MemStorage
```

Для отделения файлового сохранения от конкретного хранилища используются два интерфейса:

- `Snapshotter` - предоставляет снимок gauge- и counter-метрик для `Save`
- `Restorer` - принимает восстановленные значения через `SetGauge` и `SetCounter`

Метод `Save` записывает полный снимок в виде JSON-массива `model.Metrics`.

Метод `Load`:

- ничего не делает, если файл отсутствует
- ничего не делает, если файл пуст
- восстанавливает gauge и counter в переданный `Restorer`
- возвращает ошибку при некорректном JSON или ошибке чтения

Файловое сохранение используется только вместе с `MemStorage`.

## Ошибки

`ErrMetricNotFound` возвращается, если запрошенная метрика отсутствует.

Сервис Сервера сохраняет эту ошибку доступной через `errors.Is`, а HTTP-обработчики преобразуют её в `404 Not Found`.
