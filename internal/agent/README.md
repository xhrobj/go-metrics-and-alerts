# internal/agent

Пакет содержит runtime Агента, загрузку и валидацию конфигурации, сервис сбора метрик и формирования отчётов, а также реализации HTTP/gRPC-отправителей.

## Архитектура

```text
cmd/agent
    │ создаёт зависимости
    ▼
agent.Agent
    │ управляет циклами, очередью и worker'ами
    ▼
service.ReportingService
    ├── AgentStorage
    │   └── repository.MemStorage
    └── MetricsSender
        ├── transport/grpc.GRPCSender
        └── transport/http.HTTPSender
```

Точка входа `cmd/agent` читает конфигурацию, создаёт локальное хранилище и выбранный отправитель, собирает `ReportingService` и передаёт его в `Agent`.

## Структура

```text
internal/agent/
├── agent.go
├── report.go
├── config/
│   ├── config.go
│   ├── env.go
│   ├── file.go
│   ├── transport.go
│   └── validation.go
├── service/
│   ├── poll.go
│   ├── report.go
│   ├── sender.go
│   └── service.go
└── transport/
    ├── network.go
    ├── grpc/
    │   ├── converter.go
    │   └── sender.go
    └── http/
        └── http_sender.go
```

- `agent.go` управляет циклами сбора и формирования отчётов, очередью, worker'ами и graceful shutdown
- `report.go` формирует периодические задачи отправки и помещает их в очередь
- `config` загружает, объединяет и валидирует конфигурацию Агента
- `service` собирает метрики, хранит `PollCount`, формирует отчёты и передаёт их выбранному отправителю
- `service.MetricsSender` задаёт общий интерфейс отправки пакета метрик
- `transport/grpc` преобразует метрики в protobuf и вызывает `Metrics.UpdateMetrics`
- `transport/http` сериализует метрики в JSON и отправляет их запросом `POST /updates`
- `transport/network.go` определяет локальный IPv4-адрес Агента

## Runtime

Метод `Agent.Run` запускает три независимых цикла:

- сбор метрик Go runtime
- сбор системных метрик памяти и CPU
- формирование периодических отчётов

Runtime- и системные метрики собираются с одинаковым интервалом `POLL_INTERVAL`. Перед началом системного цикла выполняется предварительный вызов `cpu.Percent`, необходимый для последующего вычисления загрузки CPU.

Отчёты формируются с интервалом `REPORT_INTERVAL`.

Для отправки запускается отдельный worker pool. Количество worker'ов и размер буферизированной очереди равны значению `RATE_LIMIT`.

## Собираемые метрики

### Runtime-метрики

Агент сохраняет в локальное хранилище gauge-метрики из `runtime.MemStats`.

#### Общая память

- `Alloc`
- `TotalAlloc`
- `Sys`

#### Heap

- `HeapAlloc`
- `HeapSys`
- `HeapIdle`
- `HeapInuse`
- `HeapReleased`
- `HeapObjects`

#### Garbage Collector

- `NumGC`
- `NumForcedGC`
- `GCCPUFraction`
- `PauseTotalNs`
- `LastGC`
- `NextGC`
- `GCSys`

#### Внутренние структуры аллокатора

- `MSpanInuse`
- `MSpanSys`
- `MCacheInuse`
- `MCacheSys`
- `BuckHashSys`
- `OtherSys`
- `Lookups`

#### Стек

- `StackInuse`
- `StackSys`

#### Счётчики аллокаций

- `Frees`
- `Mallocs`

### Дополнительные метрики

- `RandomValue` - gauge со случайным значением, обновляемым вместе с runtime-метриками
- `PollCount` - counter с количеством runtime-опросов, которые ещё не были успешно отправлены

### Системные метрики

Через `gopsutil` собираются:

- `TotalMemory` - общий объём оперативной памяти
- `FreeMemory` - свободная оперативная память
- `CPUutilization1` ... `CPUutilizationN` - загрузка каждого логического CPU в процентах

Все системные метрики имеют тип gauge.

## Формирование отчётов

При каждом вызове `PollRuntime` значение `PollCount` увеличивается на единицу. Счётчик хранится отдельно от gauge-метрик в атомарном накопителе.

При формировании периодического отчёта `ReportingService`:

1. забирает и обнуляет накопленное значение `PollCount`
2. пропускает отправку, если после предыдущего отчёта не было runtime-опросов
3. получает снимок всех gauge-метрик из локального хранилища
4. добавляет `PollCount` как delta counter
5. возвращает готовый `Report`

Если снимок не удалось сформировать, очередь заполнена или отправка завершилась ошибкой, значение `PollCount` возвращается в накопитель через сложение. Это позволяет сохранить runtime-опросы, выполненные параллельно с формированием или отправкой отчёта.

Runtime- и системные сборщики обновляют общее хранилище независимо, поэтому снимок не гарантирует одномоментную согласованность всех gauge-метрик.

## Очередь и worker pool

Периодический отчёт помещается в очередь без блокировки. Если очередь заполнена, отчёт не добавляется, а его `PollCount` возвращается в накопитель.

```text
ReportingService.PreparePeriodicReport
                │
                ▼
          очередь Report
                │
        ┌───────┼───────┐
        ▼       ▼       ▼
     worker  worker  worker
        │       │       │
        └───────┼───────┘
                ▼
      ReportingService.Send
                │
                ▼
          MetricsSender
```

Worker'ы выполняют отправку независимо друг от друга. Поэтому при нескольких одновременных запросах порядок их завершения не гарантирован.

## Отправители

Оба транспорта реализуют интерфейс:

```go
type MetricsSender interface {
	Send(context.Context, []model.Metrics) error
}
```

### gRPC

`GRPCSender`:

- преобразует `[]model.Metrics` в `UpdateMetricsRequest`
- добавляет локальный IPv4-адрес в gRPC-метаданные `x-real-ip`
- вызывает метод `Metrics.UpdateMetrics`
- при заданном пути к CA использует TLS и проверяет сертификат Сервера
- при пустом пути к CA использует gRPC без TLS
- использует одно gRPC-соединение для всех worker'ов

При временной ошибке выполняются повторные попытки с задержками `1s`, `3s` и `5s`. Повторяются только ошибки:

- `Unavailable`
- `ResourceExhausted`

Всего выполняется одна первоначальная попытка и до трёх повторных.

### HTTP

`HTTPSender` обрабатывает пакет в следующем порядке:

```text
[]model.Metrics
-> JSON
-> gzip
-> опциональное шифрование
-> HashSHA256
-> POST /updates
```

Отправитель добавляет локальный IPv4-адрес в заголовок `X-Real-IP`.

При временной ошибке выполняются повторные попытки с задержками `1s`, `3s` и `5s`. Повторяются:

- сетевые ошибки
- статус `429 Too Many Requests`
- статусы `5xx`

Всего выполняется одна первоначальная попытка и до трёх повторных.

После окончательной ошибки любого транспорта `ReportingService` возвращает `PollCount` неотправленного отчёта в накопитель.

## Graceful shutdown

`Agent.Run` начинает graceful shutdown после отмены переданного контекста.

Последовательность завершения:

1. останавливаются циклы сбора метрик и формирования отчётов
2. ожидается завершение уже начатых операций этих циклов
3. закрывается очередь отправки
4. worker'ы обрабатывают оставшиеся в очереди отчёты и завершают активные запросы
5. `ReportingService.Flush` формирует и синхронно отправляет финальный отчёт
6. `Agent.Run` возвращает управление точке входа
7. `cmd/agent` закрывает выбранный отправитель, включая gRPC-соединение

На завершение циклов, worker'ов и финальную отправку отводится 30 секунд. При превышении тайм-аута или ошибке финальной отправки `Agent.Run` возвращает ошибку.
