# internal

В директории `internal/` находится внутренняя реализация проекта, не предназначенная для использования как публичный API. Пакеты из нее могут импортироваться только кодом, расположенным внутри корня проекта.

## Структура

```text
internal/
├── agent/      # runtime и внутренняя логика Агента
├── buildinfo/  # вывод версии, даты и Git-коммита сборки
├── encryption/ # RSA-ключи и гибридное шифрование
├── hash/       # вычисление HashSHA256
├── logger/     # инициализация zap
├── model/      # общая модель метрики
├── proto/      # сгенерированные protobuf-типы и интерфейсы gRPC
├── protocol/   # общие транспортные константы
├── repository/ # хранилища метрик
└── server/     # runtime и внутренняя логика Сервера
```

## Документация пакетов

* [`internal/agent`](agent/README.md) - сбор, подготовка и отправка метрик
* [`internal/server`](server/README.md) - запуск транспортов, обработка и хранение метрик
* [`internal/encryption`](encryption/README.md) - гибридное шифрование и работа с RSA-ключами
* [`internal/model`](model/README.md) - общая модель метрик
* [`internal/repository`](repository/README.md) - хранилища и сохранение состояния

## Сгенерированный код

Пакет `internal/proto` содержит Go-типы сообщений и интерфейсы gRPC-клиента и gRPC-Сервера, сгенерированные из [`api/metrics.proto`](../api/metrics.proto).

Сгенерированные файлы не редактируются вручную. Для их обновления используется команда:

```bash
make generate-proto
```

Общее описание контрактов находится в [документации API](../api/README.md).
