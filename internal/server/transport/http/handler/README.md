# HTTP-обработчики

Пакет `internal/server/transport/http/handler` преобразует HTTP-запросы в вызовы сервиса метрик, формирует HTTP-ответы и отправляет события аудита после успешного обновления данных.

Handler зависит от интерфейса `Service` и не связан напрямую с конкретной реализацией хранилища.

```text
HTTP-запрос
-> router и middleware
-> Handler
-> Service
-> MetricsStorage
```

## HTTP API

Полный контракт HTTP API, включая схемы запросов, ответы, статусы и транспортные заголовки, описан в [`api/openapi.yaml`](../../../../../api/openapi.yaml). Ниже приведена краткая карта маршрутов.

### JSON API

- `POST /update` - обновляет одну метрику и возвращает её итоговое значение
- `POST /updates` - обновляет пакет метрик одной операцией
- `POST /value` - возвращает значение одной метрики

### API с параметрами в пути

- `POST /update/{type}/{name}/{value}` - обновляет одну метрику
- `GET /value/{type}/{name}` - возвращает значение метрики в текстовом виде

Эти маршруты сохранены для совместимости с ранними инкрементами проекта.

### Остальные маршруты

- `GET /ping` - проверяет соединение с PostgreSQL; если БД не настроена или недоступна, возвращает `500 Internal Server Error`
- `GET /` - возвращает HTML-страницу со всеми известными метриками

## Модель и форматы данных

Общая модель метрики описана в [`internal/model`](../../../../model/README.md).

JSON-маршруты принимают `Content-Type: application/json`. Маршруты API с параметрами в пути используют текстовый формат.

Распаковка gzip, проверка подписи и расшифрование выполняются middleware до вызова обработчика. Для маршрутов записи там же выполняется проверка доверенной подсети.

## Ответственность Handler

Handler выполняет:

- декодирование и базовую валидацию входных данных
- выбор операции в зависимости от типа метрики
- вызов бизнес-логики через интерфейс `Service`
- преобразование ошибок в HTTP-статусы
- формирование JSON-, текстовых и HTML-ответов
- проверку соединения с PostgreSQL для `/ping`
- уведомление аудитора после успешной записи метрик

Для одиночного counter-обновления Handler возвращает итоговое накопленное значение. Для gauge возвращается переданное значение.

## Аудит

После успешного обновления Handler формирует событие со следующими данными:

- время обработки
- имена обновлённых метрик
- IP-адрес клиента

IP-адрес берётся из заголовка `X-Real-IP`, а при его отсутствии - из `RemoteAddr`.

Ошибка отправки события записывается в лог и не изменяет успешный HTTP-ответ.

## Границы пакета

Пакет Handler не отвечает за:

- регистрацию маршрутов
- логирование HTTP-запросов
- gzip-сжатие и распаковку
- проверку `HashSHA256`
- расшифрование тела запроса
- проверку доверенной подсети

Эти задачи выполняются соседними пакетами `router` и `middleware`.
