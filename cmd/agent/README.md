# Агент

В директории `cmd/agent/` находится точка входа Агента. Она читает конфигурацию, выбирает HTTP- или gRPC-отправитель, создаёт локальное хранилище и сервис отчётности, после чего передаёт управление `internal/agent.Agent`.

Внутренняя архитектура Агента и полный список собираемых метрик описаны в [`internal/agent`](../../internal/agent/README.md).

## Поведение Агента

Агент выполняет несколько задач:

- собирает метрики Go runtime
- собирает системные метрики памяти и CPU
- формирует пакетные отчёты
- отправляет отчёты на Сервер через очередь задач и worker pool

Количество одновременно исходящих запросов ограничивается параметром `RATE_LIMIT`. При временных ошибках транспорта Агент повторяет отправку.

## Выбор транспорта

Агент поддерживает два транспорта:

- `grpc` - используется по умолчанию
- `http` - доступен как альтернатива

Транспорт выбирается длинным флагом `--transport`, переменной окружения `TRANSPORT` или JSON-полем `transport`. Короткого флага нет.

Для выбранного транспорта используется один параметр адреса:

```text
-a / ADDRESS / address
```

Примеры:

```bash
./cmd/agent/agent -a=localhost:50051 --transport=grpc
./cmd/agent/agent -a=localhost:8080 --transport=http
```

Без `--transport` Агент использует gRPC. Адрес по умолчанию - `localhost:50051`. При переключении на HTTP необходимо указать адрес HTTP-Сервера.

## Конфигурация

Агент поддерживает четыре источника конфигурации:

- значения по умолчанию
- JSON-файл
- флаги командной строки
- переменные окружения

Приоритет источников:

```text
env > flag > JSON > default
```

Путь к JSON-файлу задаётся флагом `-c`/`--config` или переменной окружения `CONFIG`. Для самого пути действует приоритет:

```text
CONFIG > -c/--config
```

## Параметры запуска

В каждой строке указаны флаг, переменная окружения, JSON-поле и назначение параметра:

- `-a` | `ADDRESS` | `address` - адрес Сервера для выбранного транспорта, по умолчанию `localhost:50051`
- `--transport` | `TRANSPORT` | `transport` - транспорт `grpc` или `http`, по умолчанию `grpc`
- `-p` | `POLL_INTERVAL` | `poll_interval` - интервал сбора метрик, по умолчанию `2` секунды
- `-r` | `REPORT_INTERVAL` | `report_interval` - интервал формирования отчётов, по умолчанию `10` секунд
- `-l` | `RATE_LIMIT` | `rate_limit` - максимальное количество одновременно исходящих запросов, по умолчанию `5`
- `-k` | `KEY` | `key` - ключ подписи HTTP-сообщений; пустое значение отключает подпись
- `--crypto-key` | `CRYPTO_KEY` | `crypto_key` - путь к публичному RSA-ключу для HTTP; пустое значение отключает шифрование
- `-c`/`--config` | `CONFIG` - путь к JSON-файлу конфигурации

Параметры `KEY` и `CRYPTO_KEY` не используются в gRPC-режиме.

## Валидация

После объединения всех источников проверяется итоговая конфигурация:

- адрес Сервера не пустой
- транспорт равен `grpc` или `http`
- интервалы сбора и формирования отчётов положительные
- `RATE_LIMIT` положительный

## Конфигурация из JSON-файла

Пример находится в [`configs/agent.example.json`](../../configs/agent.example.json).

Значения `poll_interval` и `report_interval` задаются строками в формате `time.Duration` и должны содержать целое количество секунд, например `"2s"` и `"10s"`.

```bash
./cmd/agent/agent --config=configs/agent.example.json
```

## Примеры запуска

Через флаги с gRPC по умолчанию:

```bash
./cmd/agent/agent -a=localhost:50051 -p=2 -r=10 -l=3
```

Через флаги с HTTP:

```bash
./cmd/agent/agent -a=localhost:8080 --transport=http -p=2 -r=10 -l=3
```

Через переменные окружения:

```bash
ADDRESS=localhost:50051 TRANSPORT=grpc POLL_INTERVAL=2 REPORT_INTERVAL=10 RATE_LIMIT=3 ./cmd/agent/agent
```

Через `Makefile`:

```bash
make run-agent
make run-agent-env
make run-agent-config
make run-agent-crypto
```

HTTP-режим через `Makefile`:

```bash
make run-agent AGENT_TRANSPORT=http
```

`Makefile` выбирает `SERVER_HTTP_ADDRESS` или `SERVER_GRPC_ADDRESS` в соответствии со значением `AGENT_TRANSPORT`.

## Отправка по gRPC

Агент преобразует пакет метрик в один `UpdateMetricsRequest` и вызывает метод:

```text
metrics.Metrics/UpdateMetrics
```

Локальный IPv4-адрес Агента передаётся в gRPC-метаданных:

```text
x-real-ip: <локальный IPv4-адрес Агента>
```

## Отправка по HTTP

В HTTP-режиме Агент отправляет пакет метрик запросом:

```text
POST /updates
Content-Type: application/json
Content-Encoding: gzip
X-Real-IP: <локальный IPv4-адрес Агента>
```

Тело запроса содержит JSON-массив метрик и всегда сжимается с помощью gzip.

При заданном `KEY` запрос подписывается заголовком `HashSHA256`. При заданном `CRYPTO_KEY` сжатое тело шифруется публичным RSA-ключом, а запрос получает заголовок `Content-Encryption`.

## Graceful shutdown

Агент штатно завершает работу при получении:

- `SIGTERM`
- `SIGINT`
- `SIGQUIT`

После сигнала Агент:

1. останавливает циклы сбора метрик и формирования отчётов
2. завершает отправку отчётов из очереди и ожидает активные запросы
3. формирует и синхронно отправляет финальный отчёт
4. закрывает gRPC-соединение, если выбран gRPC

Завершение работы ограничено тайм-аутом 30 секунд.
