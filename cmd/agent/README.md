# cmd/agent

В директории находится тонкая точка входа Агента. Она читает конфигурацию, создаёт локальное repository, HTTP-отправитель и reporting service, после чего передаёт управление `internal/agent.Agent`.

Общая архитектура проекта, build info и команды Makefile описаны в [`cmd/README.md`](../README.md). Архитектура Агента и полный список метрик находятся в [`internal/agent`](../../internal/agent/README.md).

```text
cmd/agent
├── agent.Agent
├── agent/service.ReportingService
└── agent/transport/http.HTTPSender
```

## Поведение Агента

Агент запускает несколько независимых циклов:

- сбор runtime-метрик
- сбор системных метрик
- формирование batch-отчётов
- отправка отчётов через очередь задач и worker pool

Количество одновременно исходящих запросов ограничивается параметром `RATE_LIMIT`.

При временных сетевых и HTTP-ошибках Агент повторяет отправку с увеличивающимися задержками. Неотправленное значение `PollCount` возвращается в накопительный счётчик и включается в следующую попытку.

## Конфигурация Агента

Агент поддерживает флаги командной строки, переменные окружения и JSON-файл.

Приоритет источников:

```text
env > flag > JSON > default
```

Путь к JSON-файлу задаётся флагом `-c`/`--config` или переменной окружения `CONFIG`. Для пути действует приоритет `CONFIG > -c/--config`. Реализация загрузки и валидации описана в [пакете конфигурации](../../internal/agent/config/README.md).

## Параметры запуска

- флаг `-a` | env `ADDRESS` -> адрес Сервера, по умолчанию `localhost:8080`
- флаг `-p` | env `POLL_INTERVAL` -> интервал сбора runtime-метрик в секундах, по умолчанию `2`
- флаг `-r` | env `REPORT_INTERVAL` -> интервал формирования отчётов в секундах, по умолчанию `10`
- флаг `-l` | env `RATE_LIMIT` -> максимальное количество одновременно исходящих запросов, по умолчанию `5`
- флаг `-k` | env `KEY` -> ключ для `HashSHA256`; пустое значение отключает подпись
- флаг `--crypto-key` | env `CRYPTO_KEY` -> путь к публичному RSA-ключу; пустое значение отключает шифрование
- флаги `-c`/`--config` | env `CONFIG` -> путь к JSON-файлу конфигурации

## Конфигурация из JSON-файла

Пример находится в [`configs/agent.example.json`](../../configs/agent.example.json). Интервалы `poll_interval` и `report_interval` задаются строками `time.Duration`, например `"2s"` и `"10s"`.

Примеры ниже выполняются из корня репозитория после сборки Агента.

```bash
./cmd/agent/agent --config=configs/agent.example.json
```

## Примеры запуска

Через флаги:

```bash
./cmd/agent/agent -a=localhost:8080 -p=2 -r=10 -l=3
```

Через переменные окружения:

```bash
ADDRESS=localhost:8080 POLL_INTERVAL=2 REPORT_INTERVAL=10 RATE_LIMIT=3 ./cmd/agent/agent
```

Через Makefile:

```bash
make run-agent
make run-agent-env
make run-agent-config
make run-agent-crypto
```

## Формат отправки

Агент отправляет batch метрик запросом:

```text
POST /updates
Content-Type: application/json
Content-Encoding: gzip
```

Тело запроса содержит JSON-массив метрик и всегда сжимается gzip.

Агент также всегда добавляет заголовок:

```text
X-Real-IP: <локальный IPv4-адрес Агента>
```

Текущая реализация выбирает первый доступный IPv4-адрес, который не является loopback.

## Подпись и шифрование

Если задан `KEY`, Агент вычисляет хеш фактически отправляемого тела и добавляет заголовок `HashSHA256`.

Если задан `CRYPTO_KEY`, после gzip-сжатия тело шифруется:

- данные - AES-GCM
- одноразовый AES-ключ - RSA-OAEP с публичным ключом Сервера

Подпись и шифрование можно использовать независимо друг от друга.

## Graceful shutdown

Агент штатно завершает работу при получении:

- `SIGTERM`
- `SIGINT`
- `SIGQUIT`

После сигнала Агент:

1. останавливает циклы сбора и формирования отчётов
2. дожидается завершения уже начатого сбора
3. завершает отправку задач из очереди и активных worker'ов
4. отправляет финальный снимок метрик
5. завершает работу

Ожидание ограничено тайм-аутом 30 секунд.
