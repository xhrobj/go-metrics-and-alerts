# Приложения и CLI-утилиты

В директории `cmd/` находятся точки входа исполняемых программ проекта.

## Основные приложения

- [`agent`](agent/README.md) - собирает системные и runtime-метрики и отправляет их на Сервер
- [`server`](server/README.md) - принимает метрики по HTTP и gRPC, хранит их и предоставляет HTTP API для чтения

Агент и Сервер образуют основную систему сбора метрик и алертинга.

Их точки входа остаются тонкими: читают конфигурацию, создают зависимости и передают управление пакетам `internal/agent` и `internal/server`.

## Вспомогательные утилиты

- `staticlint` - запускает собственный набор статических анализаторов проекта
- `reset` - генерирует методы `Reset()` для структур с комментарием `// generate:reset`

## Как работает система

Агент периодически собирает метрики, формирует пакетные отчёты и отправляет их на Сервер по выбранному транспорту.

```text
runtime.MemStats / gopsutil
            │
            ▼
          Агент
       ┌────┴────┐
      gRPC      HTTP
       └────┬────┘
            ▼
          Сервер
       ┌────┴─────────┐
 PostgreSQL       MemStorage
                       │
                  FileStore
```

Агент использует gRPC по умолчанию. HTTP остаётся доступным через `--transport=http`.

Сервер одновременно принимает gRPC/HTTP-запросы и передаёт полученные метрики в общий сервис. Если настроено подключение к PostgreSQL, метрики хранятся в БД. В остальных случаях используется память с возможностью дополнительного сохранения в файл.

## Защита обмена

Проверка доверенной подсети поддерживается для HTTP и gRPC. Агент передаёт свой локальный IPv4-адрес:

- в HTTP-заголовке `X-Real-IP`
- в gRPC-метаданных `x-real-ip`

HTTP-транспорт дополнительно поддерживает:

- gzip-сжатие запросов и ответов
- проверку подписи запросов и подпись ответов через `HashSHA256`
- гибридное шифрование запросов по схеме RSA-OAEP + AES-GCM

Параметры `KEY` и `CRYPTO_KEY` относятся только к HTTP-транспорту. Для шифрования Агенту передаётся публичный RSA-ключ, а Серверу - соответствующий приватный ключ.

При одновременном включении сжатия, шифрования и подписи тело запроса обрабатывается в следующем порядке:

```text
Агент:
JSON
-> gzip
-> AES-GCM
-> RSA-OAEP для AES-ключа
-> HashSHA256
-> HTTP
```

```text
Сервер:
проверка HashSHA256
-> расшифрование RSA-OAEP / AES-GCM
-> распаковка gzip
-> HTTP-обработчик
```

Проверка доверенной подсети выполняется транспортным слоем до передачи запроса обработчику.

gRPC-транспорт поддерживает TLS. Сервер использует сертификат и приватный ключ, а Агент проверяет сертификат Сервера по сертификату центра сертификации. Если серверная TLS-пара и CA Агента не заданы, gRPC работает без TLS.

Локальные сертификаты и ключи создаются командой:

```bash
make grpc-certs
```

Подробности о формате ключей и реализации гибридного шифрования описаны в [`internal/encryption`](../internal/encryption/README.md).

## Сборка

```bash
make build
make build-server
make build-agent
```

При сборке через `Makefile` в бинарники Агента и Сервера передаются версия, дата сборки и хеш Git-коммита. При запуске приложения выводят эти значения в `stdout`:

```text
Build version: v0.9.0
Build date: 2026-06-16
Build commit: c0decafe42
```

Если значения не были переданы при сборке, вместо них выводится `N/A`.

## Docker Compose

Полный локальный стенд с PostgreSQL, Сервером, Агентом и проверками готовности запускается командой:

```bash
make compose-up
```

Просмотр логов и остановка:

```bash
make compose-logs
make compose-down
```

Локальная RSA-пара и сертификаты gRPC TLS создаются автоматически перед запуском Compose. Сертификаты и ключи передаются контейнерам через Compose secrets.

## Локальная конфигурация

`Makefile` автоматически читает корневой файл `.env`, если он существует. Создать его можно из примера:

```bash
cp .env.example .env
```

Файл `.env` игнорируется Git и не должен попадать в репозиторий. Агент и Сервер не читают его напрямую: `Makefile` передаёт значения через существующие флаги и переменные окружения.

Команды запуска работают и без `.env`, используя значения по умолчанию из `Makefile`.

Параметр можно разово переопределить непосредственно в команде:

```bash
make run-server TRUSTED_SUBNET=10.0.0.0/8
make run-agent AGENT_TRANSPORT=http
```

Другой env-файл можно передать через `ENV_FILE`:

```bash
make run-server ENV_FILE=.env.local
```
