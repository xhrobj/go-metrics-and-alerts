# cmd/server

В данной директории содержится код HTTP-сервера сбора метрик.

Сервер принимает метрики от агентов, хранит их в памяти и предоставляет HTTP-интерфейс для получения текущих значений.

## Конфигурация сервера

Сервер поддерживает настройку параметров через флаги командной строки и переменные окружения.

Приоритет источников конфигурации: `env > flag > default`

## Параметры запуска

- флаг `-a` или env `ADDRESS` —> адрес HTTP-сервера и порт (по умолчанию `localhost:8080`)
- флаг `-i` или env `STORE_INTERVAL` —> интервал сохранения метрик на диск в секундах (по умолчанию `300`)
- флаг `-f` или env `FILE_STORAGE_PATH` —> путь к файлу хранения метрик (по умолчанию `metrics-db.json`)
- флаг `-r` или env `RESTORE` —> загружать метрики из файла при старте (по умолчанию `false`)
- флаг `-d` или env `DATABASE_DSN` —> строка подключения к базе данных PostgreSQL (по умолчанию ``)
- флаг `-k` или env `KEY` —> "секретный" ключ для подписи и проверки HTTP-запросов и ответов (по умолчанию ``, подпись отключена)
- флаг `--audit-file` или env `AUDIT_FILE` -> путь к файлу аудита (по умолчанию ``, аудит в файл отключён)
- флаг `--audit-url` или env `AUDIT_URL` -> полный URL удалённого приёмника аудита (по умолчанию ``, удаленный аудит отключён)

## Режимы хранения метрик

Сервер поддерживает три режима хранения метрик. Режим выбирается автоматически в зависимости от переданных параметров конфигурации.

### 1. Хранение в PostgreSQL

Если задан параметр `-d` или переменная окружения `DATABASE_DSN`, Сервер использует **PostgreSQL** для хранения метрик.

В этом режиме **файловые параметры игнорируются**:

- `-f` / `FILE_STORAGE_PATH`
- `-i` / `STORE_INTERVAL`
- `-r` / `RESTORE`

Метрики читаются и записываются напрямую в базу данных.

Пример запуска:

```bash
./server -a localhost:8080 -d=postgres://metrics:password@localhost:5432/metricsdb?sslmode=disable
```

### 2. Хранение в памяти с сохранением в файл

Если параметр `DATABASE_DSN` **не задан**, но указан путь к файлу хранения, Сервер использует **хранение в памяти** с периодическим сохранением снимков метрик на диск.

Параметры:

- `-f` / `FILE_STORAGE_PATH` — путь к файлу
- `-i` / `STORE_INTERVAL` — интервал сохранения
- `-r` / `RESTORE` — загрузка метрик из файла при старте

Пример запуска:

```bash
./server -a localhost:8080 -f metrics-db.json -i 300 -r=true
```

В этом режиме:

1. Метрики хранятся в памяти
2. Периодически сохраняются в файл
3. При старте сервера могут быть восстановлены из файла

### 3. Хранение только в памяти

Если не заданы ни `DATABASE_DSN`, ни `FILE_STORAGE_PATH`, Сервер работает в самом простом режиме — **метрики хранятся только в памяти**.

Пример запуска:

```bash
./server -a localhost:8080
```

В этом режиме:

- метрики не сохраняются на диск
- при перезапуске сервера все данные теряются

## Подпись данных (SHA256)

Сервер поддерживает проверку целостности передаваемых данных с использованием SHA256.

Если задан параметр `-k` или переменная окружения `KEY`, включается механизм подписи:

- Сервер проверяет заголовок `HashSHA256` во входящих запросах
- при несовпадении хеша запрос отклоняется с кодом `400 Bad Request`
- Сервер добавляет заголовок `HashSHA256` в ответы

Хеш вычисляется от тела HTTP-запроса или ответа с учётом ключа.

Если ключ не задан, механизм подписи отключён и сервер работает в обычном режиме.

Пример запуска с подписью:

```bash
./server -a localhost:8080 -k=secret-key
```

## Аудит

Сервер поддерживает аудит успешно обработанных входящих метрик.

Аудит включается через параметры конфигурации:

- `--audit-file` / `AUDIT_FILE` - запись событий аудита в файл
- `--audit-url` / `AUDIT_URL` - отправка событий аудита на удалённый HTTP-приёмник

Если оба параметра не заданы, аудит отключен.

Событие аудита имеет формат:

```json
{
  "ts": 12345678,
  "metrics": ["Alloc", "Frees"],
  "ip_address": "127.0.0.1"
}
```

Поля события:

- `ts` - Unix timestamp события
- `metrics` - списко успешно обработанных метрик
- `ip_address` - ip-адрес клиента, отправившего запрос

### Аудит в файл

Если задан `--audit-file` или `AUDIT_FILE`, Сервер записывает события аудита в указанный файл.

Каждое событие записывается отдельной JSON-строкой в конец файла.

Пример запуска:

```bash
./server -a localhost:8080 --audit-file=audit.log
```

Пример содержимого файла:

```json
{"ts":1778862613,"metrics":["Alloc","Frees"],"ip_address":"127.0.0.1"}
{"ts":1778862620,"metrics":["PollCount"],"ip_address":"127.0.0.1"}
```

### Аудит по HTTP

Если задан `--audit-url` или `AUDIT_URL`, Сервер отправляет события аудита методом `POST` на указанный URL.

Событие отправляется в формате JSON с заголовком `Content-Type: application/json`.

Пример запуска:

```bash
./server -a localhost:8080 --audit-url=http://localhost:9090/audit
```

Успешными считаются ответы удалённого приёмника со статусами `2xx`.

### Ошибки аудита

Ошибки аудита не прерывают успешную обработку метрик.

Если метрики были успешно сохранены, но запись аудита в файл или отправка на удалённый URL завершилась ошибкой, Сервер логирует ошибку аудита и продолжает работу.
