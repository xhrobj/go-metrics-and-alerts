# cmd/server

В директории находится точка входа Сервера, который принимает метрики от Агентов по HTTP и gRPC, сохраняет их и предоставляет HTTP API для чтения текущих значений.

Общая архитектура проекта, build info и команды Makefile описаны в [`cmd/README.md`](../README.md). Lifecycle и структура Сервера описаны в [`internal/server`](../../internal/server/README.md), а HTTP-эндпоинты - в [`server/transport/http/handler`](../../internal/server/transport/http/handler/README.md).

## Конфигурация Сервера

Сервер поддерживает флаги командной строки, переменные окружения и JSON-файл.

Приоритет источников:

```text
env > flag > JSON > default
```

Путь к JSON-файлу задаётся флагом `-c`/`--config` или переменной окружения `CONFIG`. Для пути действует приоритет `CONFIG > -c/--config`. Реализация загрузки и валидации описана в [пакете конфигурации](../../internal/server/config/README.md).

## Параметры запуска

- `-a` | env `ADDRESS` -> адрес HTTP-сервера, по умолчанию `localhost:8080`
- `-g` | env `GRPC_ADDRESS` -> адрес gRPC-сервера, по умолчанию `localhost:50051`
- `-i` | env `STORE_INTERVAL` -> интервал файлового сохранения в секундах, по умолчанию `300`
- `-f` | env `FILE_STORAGE_PATH`/`STORE_FILE` -> путь к файлу метрик, по умолчанию `metrics-db.json`; `STORE_FILE` имеет приоритет над `FILE_STORAGE_PATH`
- `-r` | env `RESTORE` -> восстанавливать метрики из файла при старте, по умолчанию `false`
- `-d` | env `DATABASE_DSN` -> строка подключения PostgreSQL; пустое значение отключает БД
- `-k` | env `KEY` -> ключ для `HashSHA256`; пустое значение отключает подпись
- `--crypto-key` | env `CRYPTO_KEY` -> путь к приватному RSA-ключу; пустое значение отключает расшифрование
- `-t` | env `TRUSTED_SUBNET` -> доверенная сеть в формате CIDR; пустое значение отключает проверку
- `--audit-file` | env `AUDIT_FILE` -> файл аудита; пустое значение отключает запись в файл
- `--audit-url` | env `AUDIT_URL` -> HTTP/HTTPS URL приёмника аудита; пустое значение отключает удалённый аудит
- `-c`/`--config` | env `CONFIG` -> путь к JSON-файлу конфигурации

## Путь к файловому хранилищу

Сервер поддерживает две env-переменные:

- `FILE_STORAGE_PATH` - историческое имя
- `STORE_FILE` - имя из JSON-конфигурации и позднего инкремента

Если заданы обе, `STORE_FILE` имеет более высокий приоритет. В JSON используется поле `store_file`.

## Валидация

После объединения всех источников проверяется итоговая конфигурация:

- адрес запуска HTTP-Сервера не пустой
- адрес запуска gRPC-Сервера не пустой
- интервал сохранения неотрицательный
- `TRUSTED_SUBNET` пустой или содержит корректный CIDR
- `AUDIT_URL` пустой или содержит корректный HTTP/HTTPS URL с host

## Конфигурация из JSON-файла

Пример находится в [`configs/server.example.json`](../../configs/server.example.json). `store_interval` задаётся строкой `time.Duration`, например `"300s"`.

Примеры ниже выполняются из корня репозитория после сборки Сервера.

```bash
./cmd/server/server --config=configs/server.example.json
```

## Режимы хранения метрик

Режим выбирается автоматически по итоговой конфигурации.

### PostgreSQL

Если задан `DATABASE_DSN`, Сервер использует `PostgresStorage`. Файловые параметры в этом режиме не участвуют в хранении метрик.

```bash
./cmd/server/server \
  -a=localhost:8080 \
  -d='postgres://metrics:password@localhost:5432/metricsdb?sslmode=disable'
```

При запуске автоматически применяются миграции из каталога [`migrations`](../../migrations/README.md).

### Память и файл

Если `DATABASE_DSN` пуст, Сервер использует `MemStorage`. При непустом пути `FILE_STORAGE_PATH`/`STORE_FILE` дополнительно подключается `FileStore`.

```bash
./cmd/server/server -a=localhost:8080 -f=metrics-db.json -i=300 -r=true
```

Значение интервала определяет режим сохранения:

- `STORE_INTERVAL > 0` - периодическое сохранение снимка
- `STORE_INTERVAL = 0` - синхронное сохранение после каждого изменения

При graceful shutdown выполняется финальное сохранение. Если включён `RESTORE`, состояние загружается из файла при старте.

### Только память

Поскольку путь к файлу по умолчанию равен `metrics-db.json`, для режима только в памяти его нужно явно очистить:

```bash
./cmd/server/server -a=localhost:8080 -f=""
```

В этом режиме данные теряются после завершения процесса.

## Доверенная подсеть

Если `TRUSTED_SUBNET` задан, Сервер проверяет заголовок `X-Real-IP` на маршрутах приёма метрик:

```text
POST /update/{type}/{name}/{value}
POST /update
POST /updates
```

Запрос получает `403 Forbidden`, если:

- заголовок отсутствует
- значение не является IP-адресом
- IP не входит в настроенную CIDR-подсеть

gRPC-транспорт проверяет `x-real-ip` во входящих metadata перед вызовом `UpdateMetrics` и возвращает `PermissionDenied`, если адрес отсутствует, некорректен или не входит в доверенную подсеть. При пустом `TRUSTED_SUBNET` дополнительное ограничение отключено. HTTP-маршруты чтения, главная страница и `/ping` этой проверкой не ограничиваются.

Пример:

```bash
./cmd/server/server -t=192.168.1.0/24
```

## Подпись и шифрование

Если задан `KEY`, Сервер проверяет `HashSHA256` при наличии этого заголовка во входящем запросе и добавляет `HashSHA256` в ответы. Если заголовок передан и хеш не совпадает, Сервер возвращает `400 Bad Request`.

Если задан `CRYPTO_KEY`, Сервер загружает приватный RSA-ключ и расшифровывает входящие batch-запросы перед gzip-декомпрессией.

Подпись и шифрование можно использовать независимо друг от друга.

## Аудит

Сервер может отправлять события об успешно обработанных метриках:

- в файл через `AUDIT_FILE`
- методом `POST` на удалённый URL через `AUDIT_URL`

Если оба параметра пусты, аудит отключён. Ошибки аудита логируются, но не отменяют уже успешное сохранение метрик.

Формат события:

```json
{
  "ts": 12345678,
  "metrics": ["Alloc", "Frees"],
  "ip_address": "127.0.0.1"
}
```

Для HTTP-запросов поле `ip_address` формируется из `RemoteAddr`. Для gRPC-запросов оно берётся из metadata `x-real-ip`.

Каждое файловое событие записывается отдельной JSON-строкой. Удалённый приёмник считается успешным при ответе `2xx`.

## Graceful shutdown

Сервер штатно завершает работу при получении:

- `SIGTERM`
- `SIGINT`
- `SIGQUIT`

После сигнала Сервер:

1. прекращает принимать новые HTTP- и gRPC-соединения
2. ожидает завершения активных HTTP-запросов и gRPC-вызовов
3. при превышении тайм-аута принудительно останавливает незавершённые соединения
4. останавливает периодическое сохранение
5. сохраняет финальный снимок при файловом режиме
6. закрывает аудит и соединение с БД

Ожидание активных запросов и RPC ограничено тайм-аутом 30 секунд.
